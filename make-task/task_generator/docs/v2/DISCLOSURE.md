# 阶段披露范围、越界错误与审计

本页供平台开发与运营 AI 阅读。参与者只接收任务公开契约、当前虚拟时间和桥接结果，不接收真实分段、时间映射、私有披露策略或审计数据库。

## 平台传入范围

创建 episode 时，控制器根据已验证并冻结的研发期与七段 `windows` 生成 `disclosure.private.json`，绑定版本和哈希。每次打开研发服务或创建可信引擎容器时都重新校验。缺少范围、起止倒置、超出冻结范围或哈希不一致时停止，不能回退为整库查询。

私有策略使用 `schema_version=finlab.disclosure.v1`，保存 `episode_id`、`dataset_id`、`freeze_hash`、`interval="[start,stop)"`、`stages` 和 `policy_hash`。`stages`中的每项为 `stage/start/stop`，第0项是研发期，第1至7项是到该段为止的累计范围。binding和state锚定策略哈希，不能单独替换文件扩大权限。研发及七段的既有windows生成规则继续使用；候选题不会因此预填实际日期。

运营方可以在运行binding中提供`stage_windows`，每项包含`segment/start/stop`。须提供0至7共八个连续区间，使用真实YYYY-MM-DD边界，覆盖完整任务，且每段至少两个交易日；不提供时沿用现有按交易日分段程序。候选包不填实际边界。私有披露策略的格式见`schemas/disclosure_policy.v1.schema.json`。缺少新策略的既有episode会停止，须由平台核验后重新绑定；不能在已完成的运行上静默生成新权限文件。

范围统一为 `[start, stop)`：开始包含、结束不包含。内部日期时间以真实时间和上海时区处理；对参与者的请求、响应和提示只使用虚拟时间。

|查询环境|可查询范围|推进依据|
|---|---|---|
|研发服务|研发期，加此前已成功提交的所有正式段|控制器已提交状态|
|研发回测中的策略|该次研发运行范围，并受当前事件时钟限制|可信引擎事件|
|正式策略|研发期及本段之前的历史，并受本段当前事件时钟限制|可信引擎事件|

披露范围是累计范围，不要求每段重新失去此前历史。策略在某段开始运行不等于已获得该段全部行情；它仍只能使用当前事件时点已经可见的记录。客户端不能传入阶段号、扩大范围或推进时钟。

研发服务的既有命令保持不变：

```powershell
finlab bridge serve --episode work_v2/episode --host 127.0.0.1 --port 8766
```

范围从 episode 的平台私有配置取得，不添加参与者可修改的范围参数。正式策略的桥接由可信引擎创建，不复用研发服务的已解锁时钟。

## 请求与返回的双重检查

显式时间请求必须完整位于允许范围内。完全越界或只有一部分越界都整次拒绝，不能返回其中合法部分。省略时间参数时，仅查询当前允许范围；省略参数、分页、倒序、`pro_bar`、动态方法或直接 HTTP 都不能扩大权限。

时间参数按接口登记的类型和选择语义识别。日线按日期精度检查，分钟与时间戳按接口声明的精度检查；年、月和季度不能作为绕过边界的入口。无法确定选择语义时应补规则，由平台重新核验，不能猜测后放行。

冻结manifest为每个接口保存`time_query_rules`。运营方可在freeze的接口契约中用`query_time_rules`显式登记参数路径、`role`（`lower/upper/select`）与`target`（`event_at`或该接口登记字段）；嵌套路径使用点及`[]`。月份、季度和年份按完整周期检查，逗号选择与数组逐项检查，任一项越界拒绝整个请求。参数中的日期文本若没有可靠选择语义，返回`TIME_SELECTION_UNCLASSIFIED`，不按普通文本透传。

每次查询固定一份范围、事件时钟和策略版本快照。返回前再次检查记录范围与 `available_at`，先限制可见修订，再选最新可见版本，最后分页；并发请求不共享可变权限快照。

这不是对记录里每个日期字段做简单大小比较。已公告的未来到期日等元数据仍可通过已登记的例外返回；它们的可见性必须有依据。`visible_history` 不允许扩大行情范围，也不能把未来修订或当前资料冒充过去可见版本。名称与代码继续保持原值。

`visible_history`当前仅允许审核过的基础元信息接口：`stock_basic/fund_basic/index_basic/fut_basic/opt_basic/cb_basic/bond_basic/stock_company`，仍须证明历史可见性。复权因子、估值、涨跌停、行情及历史成分序列不能套用该例外。例外只作用于已可见记录中的独立日期字段，不授权显式查询未来日期。

构造示例：允许`[2400-01-01, 2400-02-01)`，查询`start_date=24000110,end_date=24000201`整次报越界；改为`end_date=24000119`可通过阶段范围检查。若正式策略当前事件仅到2400-01-15，即使查询2400-01-19仍在该段范围内，也会被事件时钟拒绝。这只是虚拟时间示例，不是系统默认配置或实际市场数据。

## 越界错误

HTTP 状态为 `403`，响应不含 `data`：

```json
{
  "code": -1,
  "error_code": "TIME_RANGE_EXCEEDED",
  "msg": "查询时间超出本阶段允许披露范围，本次请求未返回数据。",
  "request_id": "请求唯一编号"
}
```

兼容 SDK 抛出 `LabError`（`ValueError` 子类），通过 `.code`、`.message`、`.request_id` 保留错误码、错误信息和请求编号。不得转换为空 DataFrame，不能将越界解释成停牌、无成交或零收益。查询跨界时先修正请求；尚未披露的数据须等待平台成功提交后开放，不通过切换上游、修改令牌或反复重试绕过。

公共错误不包含真实日期、实际偏移、私有路径或未披露数据。请求编号用于让运营方定位对应记录。

## 私有审计与故障

审计使用支持事务和并发写入的 SQLite。研发服务写入 episode 下的 `bridge_audit.private.sqlite`；容器内服务写入当前 job 的 `artifacts/bridge_audit.private.sqlite`。目录随平台运行记录保留，容器退出和清理不会删除数据库。

记录内容包括请求编号、episode、阶段、job、接口、清理后的查询参数、请求范围、实际生效范围、事件时钟、披露策略版本/哈希、处理结果和拒绝原因。不保存访问令牌、上游凭证或行情正文。数据库中的真实时间与权限依据只供平台追踪，不交给策略，不加入公开导出白名单。

容器请求还记录提交代码的`submission_hash`；研发服务的交互查询没有提交版本时记为null。桥接与内部RPC令牌仅在内存中登记用于脱敏，即使令牌被复制到普通参数值，也会在日志落盘前替换。引擎成功结束时先停止并等待所有桥接请求、完成SQLite WAL检查点，再计算产物哈希和提交，防止日志在验收过程中继续变化。

平台可只读查看最近记录，`--job`用于选择某次容器运行；不传时查看研发服务日志：

```powershell
finlab bridge audit --episode work_v2/episode --limit 100
finlab bridge audit --episode work_v2/episode --job JOB_ID --limit 100
```

此入口读取私有数据库，输出仅供平台运营排查，不转发给参与者。数据库表为 `query_events`，每条记录的 `body` 保存JSON审计内容。

审计写入失败时返回 HTTP `503`、`error_code=BRIDGE_AUDIT_UNAVAILABLE`，不返回行情。运营方检查存储可写性和空间后重试，不能关闭审计换取返回数据。

越界请求和失败 job 都不推进阶段。只有正式运行结果和可信检查点完成校验、控制器原子提交成功后，研发端才增加该段可见范围；重试仍从上一次已提交状态开始。

## 验收定位

边界、部分越界、省略日期、年月季度、分钟/时间戳、分页与包装接口、修订版本、并发快照、审计故障及公开导出隔离应由自动测试覆盖。容器验证另检查日志在清理后保留。真实 Tushare 接口测试和合成回放测试分别记录，未执行项目不能写为通过。

本轮结果见[阶段披露验证摘要](../disclosure_validation_v2.json)、[完整自动测试](../unit_tests_v2.json)和[实际Docker验收](../acceptance_v2.json)。交付镜像ID与验收报告逐项核对，历史候选快照继续按原清单验证，不因增加运行协议而改成已批准新题。
