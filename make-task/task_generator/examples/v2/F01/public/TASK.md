# 整理区间突破后的跟踪、失败退出与再入场

> v2任务规格。规格接纳、数据绑定和运行接入分别记录，当前状态以task_input.draft.json与平台登记记录为准；不要求人工审批。

研究目标：如何使区间识别、突破确认、失败处置与再次参与形成可维护的状态流程？

## 运行协议

先在研发期开发首版，再经历七段逐步揭晓的正式期。每段运行时冻结代码；完成后可以保持、调参或修改逻辑。
现金、持仓、未完成订单和JSON memory连续。修改不重置账户，不覆盖过去结果。全部七段的连续账户用于评价。
实际虚拟时间范围、数据版本和分段边界在绑定后确定。

## 研究决策

- 研究只使用已完成K线的整理区间、边界更新和失效状态。；相互影响：边界更新改变确认门槛及失败判断，不可事后重画区间。
- 比较突破后的等待、量价确认与可成交时点。；相互影响：等待会改变持有期、T+1库存和机会排序。
- 研究突破失败与正常回踩的区别及已有仓位退出。；相互影响：退出时刻约束再次参与，不能用未来最低价标记假突破。
- 设计失败后冷却与结构重建后的再次参与。；相互影响：memory保留旧失败状态，与新区间编号和旧持仓兼容。
- 在同时触发的候选间分配现金和权重。；相互影响：资金竞争与T+1不可卖仓位影响信号实际实现。

可研究的参数与结构选择：

- {"name": "confirmation_and_reentry", "type": "structured", "description": "确认、失败、冷却及重入规则相互作用；由Agent研究，不给最佳阈值。"}

持续维护依据：后续数据可能使区间结构和失败模式变化，需要判断调整结构、确认还是退出；每次维护必须接住已持仓和旧失败状态。这是可维护性假设，尚无轨迹证明长程难度。
