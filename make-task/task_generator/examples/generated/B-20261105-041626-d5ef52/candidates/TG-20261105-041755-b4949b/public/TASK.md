# 风险预算表达与恢复执行链：暴露刻度选择、分步减仓可行性与逐级恢复准入

> v2任务规格。规格批准、数据绑定和运行接入分别记录，当前状态以task_input.draft.json与平台登记记录为准。

研究目标：在国内股票或ETF日线环境中，仅使用已完成交易日收盘后可见的价格、成交与账户信息：如何把组合风险状态（已回撤幅度、近期已实现波动、仓位与现金集中度）整理为可审计的预算表达刻度（例如暴露比例、名义上限或现金留存比例），并在缩减触发时按当时可成交约束——T+1新买不可卖、已挂未成交单、单票权重上限与现金不足——决定缩减到哪一档、哪些待办失效、未完成减仓如何顺延；缩减后又如何按逐级恢复条件部分回升预算，而不是一次性回到原预算，使预算占用、未完成待办与目标预算的差额在跨段维护中连续可核？

## 运行协议

先在研发期开发首版，再经历七段逐步揭晓的正式期。每段运行时冻结代码；完成后可以保持、调参或修改逻辑。
现金、持仓、未完成订单和JSON memory连续。修改不重置账户，不覆盖过去结果。全部七段的连续账户用于评价。
实际虚拟时间范围、数据版本和分段边界在绑定后确定。

## 研究决策

- 仅用当时已收盘的价量与账户数据，定义可审计的组合风险状态证据：已实现回撤幅度、近期已实现波动、仓位与现金集中度；规定各证据的读取窗口、更新时点、优先与去重规则，使同一段回撤不会被重复计为多档状态，且状态读取结果可被后续预算刻度直接引用。；相互影响：状态证据集合与读取口径决定risk_budget可用的预算刻度种类与取值范围；同时接收来自state_migration的回指，使跨段承接后的状态读取口径与已建仓位、未完成待办保持一致，避免状态在段间被错误重置或重复累计。
- 把状态识别给出的风险证据映射为可执行的预算表达刻度（暴露比例、名义上限或现金留存比例之间的取舍），并规定预算占用与目标预算差额的核算方式，包括已建仓、挂单占用与现金留存如何计入当期已用预算；预算刻度须能被后续缩减与恢复按档阅读。；相互影响：风险状态证据决定预算刻度的选择与档位；同时接收来自recovery_policy的回指，使恢复准入结果改变下一期目标预算档位，并让预算占用差额成为恢复判定的输入。
- 在缩减触发时，依据预算档位与当时可成交约束（T+1新买不可卖、已挂未成交单、单票权重上限、现金不足）决定缩减到哪一档、哪些挂单撤销、哪些持仓分批减仓，并规定未完成减仓的顺延与残余敞口记录方式；缩减执行结果须可审计、可承接。；相互影响：缩减触发由risk_budget档位与占用差额驱动；缩减产生的结果同时写入recovery_policy作为恢复起点，并写入state_migration以承接未完成减仓、撤单记录与残余敞口，使下一段能识别预算占用与目标预算的差额。
- 定义缩减后的逐级恢复条件与节奏：哪些证据须独立于被覆盖的回撤记忆、恢复须分几级、每级准入需要多长的可观察延续；规定恢复准入如何读取预算占用差额与残余敞口，使部分恢复不依赖一次性回到原预算。；相互影响：恢复条件读取drawdown_response留下的缩减起点与残余敞口，并回指risk_budget，使恢复结果直接改变下一期目标预算档位；恢复准入过程同时经由state_migration承接，保证恢复节奏在段间连续。
- 定义跨段承接规则：预算档位、预算占用、已建仓、未完成减仓、已撤挂单记录与残余敞口如何持久化到JSON memory并在下一段恢复；规定缩减未完成与恢复进行中的中间状态如何被识别，避免段间重复缩减或跳档恢复。；相互影响：承接来自drawdown_response的缩减结果，并回指state_identification，使下一段状态读取口径与已承接的预算档位、残余敞口一致，防止状态证据被重复累计或错误重置。

可研究的参数与结构选择：

- 状态证据读取窗口长度（回撤、已实现波动、集中度各自窗口）
- 风险证据合并的优先与去重规则开关
- 预算表达刻度选择（暴露比例/名义上限/现金留存比例）
- 预算档位数量与各档阈值
- 缩减触发确认时点与忍让窗口
- 分步减仓每批比例与最小可减单位
- 挂单撤销与残余敞口顺延规则开关
- 恢复分级数量与每级准入的延续观察长度
- 恢复准入读取的预算占用差额阈值

持续维护依据：后续分段揭晓的观察可能显示：风险状态证据在缩减后因仓位下降而分布改变，导致状态识别口径漂移；预算刻度选择在不同波动环境下使缩减与恢复的可执行性不同；缩减触发的分步减仓与T+1约束可能留下残余敞口，使预算占用与目标预算差额长期存在；恢复准入过松会导致反复触发缩减，过紧则使预算长期偏低。维护时可选择保持现有证据窗口与恢复节奏、调整预算刻度种类或恢复分级条件，或重构状态证据合并与承接逻辑；不承诺每次维护提升收益，也不要求实盘盈利。
