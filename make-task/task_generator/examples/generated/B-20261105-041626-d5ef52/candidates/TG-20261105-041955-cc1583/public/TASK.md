# 横截面相对强弱排名中候选池资格的反向协商：流动性集合边界、留存门槛与现金预算的联合维护

> v2任务规格。规格批准、数据绑定和运行接入分别记录，当前状态以task_input.draft.json与平台登记记录为准。

研究目标：在国内股票或ETF日线环境中，仅用当时已收盘可见的量价与涨跌停数据：相对强弱特征应如何定义才能与成交活跃度的度量口径一致；成交活跃度不只是入场前的静态筛选，而应由当期资金分配结果（仓位碎片化程度与剩余现金）反向收缩或恢复下一期可参与排名的股票集合；当可参与集合随现金预算逐期增删时，同日排名的分母随之变化，继续持有的门槛必须与变化后的排名重新协商，而不是沿用上一期的留存标准；研究需给出这一闭环在分段维护中可解释、可接续的决策规则。

## 运行协议

现金、持仓、未完成订单和JSON memory连续。修改不重置账户，不覆盖过去结果。全部七段的连续账户用于评价。
实际虚拟时间范围、数据版本和分段边界在绑定后确定。

## 研究决策

- 定义当日收盘后即可计算的相对强弱特征：在统一的已完成窗口上构造收益与波动标准化量，并让成交活跃度度量使用同一窗口与同一复权口径，避免特征与筛选口径不一致导致的排名漂移。；相互影响：特征口径确定后，liquidity_filter 才有一致的活跃度输入；capital_allocation 的结果会回指本模块，要求说明现金碎片与持仓权重上限如何约束可用于计算特征的窗口长度与样本完整性。
- 用当时已知的成交额与涨跌幅限制状态界定可参与排名的候选集合：排除当日无成交、涨跌停封死或活跃度不足的标的，并记录集合的逐期构成。；相互影响：集合随 capital_allocation 回指而收缩或恢复：当期现金不足造成持仓碎片时，下一期可用参与集合应相应收窄；集合变化后 rank_aggregation 的排名分母改变，必须重新计算而非沿用缓存排名。
- 在当期可参与集合上合成相对强弱得分并给出同日排名，明确得分标准化方式与并列处理。；相互影响：排名分母由 liquidity_filter 决定，排名结果直接决定 holding_buffer 的入选与留存判断；capital_allocation 回指特征口径后，排名需在参数版本更新时重建而非增量修补。
- 分设买入门槛与继续持有门槛，使既有持仓在排名轻微下滑时保留，并给出缓冲宽度随集合规模变化的自适应规则。；相互影响：缓冲宽度受 capital_allocation 反馈影响：现金碎片化时缓冲不应无限放宽；缓冲结果传给 capital_allocation 作为换仓候选与留存名单的输入。
- 在留存名单与新增候选之间分配资金，考虑单票权重上限、现金余额、T+1 新增不可卖约束与剩余现金，并把分配结果的碎片化程度回写为下一期集合与特征口径的约束。；相互影响：本模块回指 liquidity_filter 与 feature_definition：分配造成的碎片化与现金不足改变下一期可参与集合与可用特征窗口；同时接收 holding_buffer 的留存名单，形成资格集合与留存门槛的双向协商，而非单向链。

可研究的参数与结构选择：

- 特征回看窗口长度
- 活跃度阈值分位
- 买入排名门槛
- 继续持有排名门槛
- 缓冲宽度随集合规模的自适应系数
- 单票权重上限
- 现金留存比例

持续维护依据：后续正式期揭晓的观察可能显示：可参与集合逐期变化导致排名分母不稳定，留存门槛在集合收缩时过于严苛而频繁换仓，或现金碎片化使特征窗口不可用。这些观察应促使研究者在保持机制不变的前提下调整集合边界规则、缓冲宽度或分配约束，或保留现有逻辑；也可能显示闭环依赖在跨段迁移时使旧持仓与现金不兼容，需修正状态承接规则。维护不保证每次调整都提升收益，也不承诺实盘盈利。
