# FG/SA跨品种关系重估中的残差参与与保证金预算维护

> v2任务规格。规格批准、数据绑定和运行接入分别记录，当前状态以task_input.draft.json与平台登记记录为准。

研究目标：在国内期货真实分合约日线环境中，仅使用已完成交易日收盘后可见的字段：如何在FG与SA两条真实合约腿上估计当时可见的滚动对冲关系并转成有符号整数手数；当残差偏离触发参与条件时如何推进建仓与退出，而当对冲比例本身漂移时又如何把它与普通残差波动区分开，暂停参与并重新估计；重新估计与合约换月后旧腿、未成交残余敞口与已确认的对冲比例版本如何迁移，使分段研发中的头寸与状态连续可核？

## 运行协议

先在研发期开发首版，再经历七段逐步揭晓的正式期。每段运行时冻结代码；完成后可以保持、调参或修改逻辑。
现金、持仓、未完成订单和JSON memory连续。修改不重置账户，不覆盖过去结果。全部七段的连续账户用于评价。
实际虚拟时间范围、数据版本和分段边界在绑定后确定。

## 研究决策

- 仅用当时已完成日线，在FG与SA各自可交易合约中按剩余期限、成交活跃度与更早可见的到期信息选定本期实际参与的一条FG腿与一条SA腿，并记录选定理由与备选顺序，供后续换月与重新估计复用。；相互影响：选定腿集合直接决定hedge_estimation的样本与口径；状态迁移后不得自动沿用旧腿集合，需重新走month_selection。
- 在选定两腿上估计当时可见的滚动对冲比例，处理价格刻度、合约乘数与有符号整数手数换算，并把残差尺度与比例版本标注为可复现的估计结果。；相互影响：比例版本决定entry_exit的残差口径与参与阈值含义；relationship_monitoring判定比例漂移后回到本模块重估，使重估成为闭环而非一次性校准。
- 定义残差偏离达到参与条件后的入场、分批建仓、持有时限与退出规则，逐腿撮合并容许部分成交与残余敞口，退出时明确两腿先后与残余敞口清理。；相互影响：退出结果与残余敞口进入relationship_monitoring作为关系可用性证据；预算不足时的缩减请求会改变可入场手数与退出节奏。
- 以残差尺度变化与对冲比例漂移为证据，判定关系仍可用、需重估、或需暂停参与，并给出暂停后恢复参与的前置条件；区分普通残差波动与比例断裂，避免重复触发。；相互影响：触发重估即回到hedge_estimation并失效旧阈值含义；触发暂停与恢复进入margin_budget决定预算占用与缩减。
- 按双腿真实价格、保证金要求、合约乘数与费用估算占用，在预算约束下决定配对手数、缩减与暂停参与，并处理保证金上升时的未成交与残余敞口。；相互影响：预算占用与释放结果经state_migration写入跨段状态；预算收紧会回压entry_exit的可入场手数。
- 定义版本跃迁时旧腿、未成交残余敞口、已确认对冲比例版本与监控状态的迁移规则，明确哪些必须重估、哪些可保留，保证现金、持仓、未完成订单与memory连续。；相互影响：迁移结果重新约束month_selection的候选腿集合与hedge_estimation的样本起点，使迁移不是被动记账而是改变下一段研究可用条件。

可研究的参数与结构选择：

- 对冲估计的回看长度与更新频率
- 残差参与阈值的波动标准化方式
- 暂停参与与恢复重估的前置条件
- 单腿手数上限与预算占用比例
- 残余敞口清理的等待与撤单规则
- 换月前后的候选腿排序偏好

持续维护依据：后续揭晓的已收盘数据可能显示对冲比例缓慢漂移、残差尺度变化或某腿活跃度转移，这会促使在relationship_monitoring与month_selection之间调整判断门槛、更换腿对或改变重估频率，也可能促使保持原设定；保证金变化与部分成交残余敞口会暴露预算与撮合假设的偏差，需在margin_budget与state_migration中修订规则并保持旧状态可解释。维护目标是让关系漂移、保证金暴露与跨段状态兼容可被持续检验，不承诺每次维护提升收益。

## 数据与执行

行情通过Tushare协议桥接器查询。使用环境变量MARKET_BRIDGE_URL和MARKET_BRIDGE_TOKEN，详见DATA_API.md。
名称与代码保持真实；全部时间字段使用虚拟时间，仅表示事件顺序和可见时点。
虚拟年份不对应真实历史年份，不得按年份预设股灾、政策、节假日或未来事件，也不得反推实际时期。
交易日以服务返回日历为准，不按虚拟日期的星期猜测；策略只能根据当时已可见数据形成判断。
只能使用当前可见信息，不访问外网。指数仅用于查询与基准，不可下单。
AKQuant 0.3.76执行撮合；收盘后决策、下一根行情开盘撮合。期货多腿逐腿撮合，可能部分成交，需处理残余敞口。
交易单位、T+0/T+1、费用、公司行为、价格限制、保证金与结算按绑定后的runtime_profile固定。
资源预算尚未选择，必须由本人先运行finlab setup；CPU、内存和时限由本人明确配置，AI不能代填。
任务只提供非生效的CPU/内存建议；单次运行时限由使用者本人明确选择，不预填。
规则未绑定时不能正式运行。原始价格用于撮合，研究复权数据不得重复计入公司行为收益。
