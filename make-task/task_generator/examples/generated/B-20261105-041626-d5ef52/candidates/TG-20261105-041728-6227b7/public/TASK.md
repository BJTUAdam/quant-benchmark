# 相对强弱排名中的候选池资格回溯：流动性集合边界与留存门槛的反向协商

> v2任务规格。规格批准、数据绑定和运行接入分别记录，当前状态以task_input.draft.json与平台登记记录为准。

研究目标：在国内股票或ETF日线环境中，仅用当时已收盘的量价数据：如何用同一完成口径的收益与活跃度定义相对强弱特征，并让流动性筛选不是一次性的入场前置，而是由当期资金分配结果（仓位碎片化程度与剩余现金）反过来收缩或恢复下一期可参与排名的资格集合；当资格集合随现金预算变化而增删时，同刻排名分母随之改变，继续持有门槛与排名合成必须重新协商，使留存名单在排名噪声、换仓可执行性与现金约束之间保持可解释、可接续？

## 运行协议

先在研发期开发首版，再经历七段逐步揭晓的正式期。每段运行时冻结代码；完成后可以保持、调参或修改逻辑。
现金、持仓、未完成订单和JSON memory连续。修改不重置账户，不覆盖过去结果。全部七段的连续账户用于评价。
实际虚拟时间范围、数据版本和分段边界在绑定后确定。

## 研究决策

- 定义回看窗口内可比的相对强弱特征：只用已完成日线的收盘与复权口径，明确收益口径与波动标准化的处理方式，并规定在复权因子或停牌造成缺失时的跳过与标记规则，使同一口径同时可用于强弱计算与活跃度度量。；相互影响：与liquidity_filter共享同一完成窗口与收益口径，避免强弱排序与活跃度筛选使用不一致的时间尺度；特征窗口长度直接决定排名分母变化后排名结果的稳定性，进而影响holding_buffer的宽度设定。
- 以当时已知的成交额和成交量水平界定可参与排名的资格集合，并规定资格的连续期数要求与失效后的有效期；资格集合是排名分母，而非在排名之后剔除。；相互影响：其集合边界受capital_allocation回指：当期分配后仓位碎片过多或剩余现金不足以支撑最小交易单位时，须收缩资格集合；同时feature_definition的缺失处理规则决定资格判定的连续性，二者共同决定rank_aggregation的输入集合大小。
- 在资格集合内合成同日排名：规定强弱得分的合成方式、并列得分处理与资格集合变化日的排名可比化方法，避免池子增删导致排名跳变被误读为信号变化。；相互影响：接收feature_definition与liquidity_filter双输入，输出排名序列；其分母变化直接决定holding_buffer的有效宽度，并使资本分配后的碎片化能追溯为排名口径问题。
- 分设买入门槛与继续持有门槛，规定留存名单在排名劣化到何种程度才触发替换候选队列，并明确资格集合收缩时已持有但失格标的的处置优先级。；相互影响：上游连接rank_aggregation的排名结果，下游受capital_allocation约束：资金分配造成的仓位碎片会压缩留存名单，要求继续持有门槛在下一轮评估中被动态调整。
- 在多个候选间分配资金并保留现金缓冲，规定单票权重上限、最小可交易单位与剩余现金的处置方式，并记录分配结果作为下一期资格集合收缩或恢复的判断依据。；相互影响：对holding_buffer形成约束并回指liquidity_filter与feature_definition，使预算结果重新定义可参与排名的集合与特征窗口的可用性，形成资格集合与留存门槛的双向闭环。

可研究的参数与结构选择：

- 强弱特征回看窗口长度
- 活跃度度量的比较尺度
- 资格连续期数与失效有效期
- 排名合成方式与并列处理
- 买入门槛与继续持有门槛的差距
- 单票权重上限与现金缓冲比例
- 资格集合收缩的触发条件

持续维护依据：后续分段揭晓的观察可能表现为排名名单频繁更替、留存名单收益贡献与换仓成本不匹配、或资格集合收缩后留存门槛随即失效。若排名稳定性在纳入资格集合变化后显著下降，维护者应保持或收紧资格连续期数并放宽继续持有门槛；若成本敏感性显示换仓收益被侵蚀，则调整单票权重上限与现金缓冲而非仅改阈值；若信号与实际成交持仓的差距扩大，应检查资格失效后的旧持仓处置顺序。每次维护不承诺提升收益，仅要求行为可解释、状态可核。
