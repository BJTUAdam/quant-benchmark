# 同品种多月份期限曲线的斜率变化与动态配对选择：可交易合约对集合、整数手数与到期迁移的联合维护

> v2任务规格。规格批准、数据绑定和运行接入分别记录，当前状态以task_input.draft.json与平台登记记录为准。

研究目标：在国内期货真实分合约日线环境中，仅使用已完成交易日收盘后可见的字段：同一品种同时存在多个到期月份时，如何先把各月份价格按剩余期限化为可比的曲线口径，再由多月份曲线的斜率与形态变化生成当时可见的信号；该信号如何从可交易月份集合中选出本期实际参与的一条合约对，而不是固定近远月对；当两腿的真实乘数、价格刻度与整数手数导致配对难以按比例成立时，如何决定参与、退出与持有时限；当某一腿临近到期或流动性转移时，如何安排平旧开新并承接口径版本与未完成换腿的中间状态，使分段研发中配对与曲线口径连续可核？

## 运行协议

先在研发期开发首版，再经历七段逐步揭晓的正式期。每段运行时冻结代码；完成后可以保持、调参或修改逻辑。
现金、持仓、未完成订单和JSON memory连续。修改不重置账户，不覆盖过去结果。全部七段的连续账户用于评价。
实际虚拟时间范围、数据版本和分段边界在绑定后确定。

## 研究决策

- 用已完成日线中的到期月份信息与当时可见价格，把同一品种各月份表达为可比期限口径，明确剩余期限差、价格刻度与合约乘数差异的处理方式，并记录口径版本。；相互影响：为曲线斜率与形态提供同一尺度的输入；口径版本变化会改变curve_signal的阈值含义，并作为state_migration需要承接的迁移对象。
- 基于可比期限口径下的多月份价格，定义当时可见的曲线斜率与形态变化信号，说明信号方向、强度与失效条件，不使用事后数据。；相互影响：信号输入来自tenor_normalization；信号结果决定pair_selection的候选排序，并在state_migration恢复后需按新口径重新确认。
- 从当时可交易且有可见成交的月份中选出本期实际参与的一条合约对，综合曲线信号、剩余期限匹配与流动性，给出配对理由与备选对。；相互影响：依赖curve_signal与tenor_normalization；选出的真实两腿决定entry_exit的标的与移仓起点，且state_migration后的候选对集合不得自动沿用旧选择。
- 在选定的真实两腿上按有符号整数手数决定参与、退出与持有时限，处理逐腿撮合可能的部分成交与残余敞口。；相互影响：接收pair_selection的两腿；退出结果影响roll_policy的触发时点与margin_budget之外的保证金占用变化。
- 在某一腿临近最后交易日或流动性转移前，安排平旧开新的顺序，核算移仓成本与过渡期间的残余敞口。；相互影响：由entry_exit的持仓与退出状态触发；移仓结果需要state_migration承接旧配对库存与未成交换腿。
- 版本更新或口径调整时迁移曲线口径版本、已选合约对、旧腿持仓与未完成换腿中间状态，规定恢复后是否需重新确认信号与配对。；相互影响：承接roll_policy的移仓中间态；迁移后的口径与记忆状态回指pair_selection与curve_signal，要求重新确认后才会继续参与。

可研究的参数与结构选择：

- 曲线信号的观察窗口长度
- 斜率或形态变化的确认强度阈值
- 候选月份对的最小剩余期限差
- 流动性筛选的最小成交量与持仓量门槛
- 配对时两腿的整数手数比例允许偏差
- 持有时限上限
- 移仓触发距最后交易日的前置幅度
- 口径版本更新后重新确认所需的观察长度

持续维护依据：后续分段揭晓的观察可能显示某些月份对的流动性格局或曲线斜率形态发生漂移，从而使既有曲线口径与配对选择不再适用；此时需决定保持现有阈值、调整口径参数或修改信号与配对逻辑。已建配对库存和未完成换腿必须在口径版本更新时被显式承接，否则移仓与保证金占用会出现无法对账的断层。维护不承诺提升收益，仅要求行为可解释、可接续。
