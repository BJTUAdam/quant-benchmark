# 整理区间突破后的确认缺失处置：区间失效与突破未确认的区分、失败退出与再入场预算回压

> v2任务规格。规格批准、数据绑定和运行接入分别记录，当前状态以task_input.draft.json与平台登记记录为准。

研究目标：在国内股票或ETF日线环境中，仅用当时已收盘数据界定整理区间并给出突破信号；当突破后价格未能完成确认、又退回区间内部时，如何把“区间本身被证伪（结构失效）”与“区间仍有效但突破未获确认”两路证据区分并去重，转化为对已有候选持仓的退出与对已挂未成交单的撤销，而不是把两种情况都当成普通止损；退出与撤销造成的预算缩减与现金碎片，又如何反过来收窄下一段区间识别的有效边界与突破确认的等待宽度，使整个状态生命周期在跨段维护中连续可核？

## 运行协议

先在研发期开发首版，再经历七段逐步揭晓的正式期。每段运行时冻结代码；完成后可以保持、调参或修改逻辑。
现金、持仓、未完成订单和JSON memory连续。修改不重置账户，不覆盖过去结果。全部七段的连续账户用于评价。
实际虚拟时间范围、数据版本和分段边界在绑定后确定。

## 研究决策

- 仅用已完成日线收盘数据界定整理区间：区间上下边界、成立所需的最短驻留与失效条件的表达方式（例如边界被连续收于区间之外多久视为结构失效）。需要说明区间有效期如何随新数据滚动更新，以及更新时对旧边界是替换、扩展还是重置。此模块只决定“当前是否存在有效区间及其边界”，不决定是否入场。；相互影响：区间边界与有效期直接决定突破信号的空间位置；同时向 failure_exit 提供“结构失效”的判定依据，使退出模块能区分区间被证伪与突破未确认。capital_allocation 的预算缩减结果会反向收窄该模块接受的区间宽度有效范围，形成资金约束对区间识别的回压。
- 在区间边界给定后，定义突破的确认依据与等待时机：例如需要连续几根完成日线收于边界之外、或以收盘价相对边界的持续性而非盘中穿越作为确认；并明确确认之前是否允许以试探性手数参与、以及该试探的规模上限。此模块只回答“何时算确认、确认前可做什么”，不回答失败后如何退出。；相互影响：接收 range_detection 的边界与有效期作为输入；其确认结论是 failure_exit 判定“突破未确认”的前提。同时受 capital_allocation 回压：预算缩减后允许的试探规模与最长等待宽度被收紧，从而改变什么算容易达成的确认。
- 定义两类失败路径并给出优先级与去重规则：一是已持有候选因区间结构失效而退出，二是突破始终未获确认且价格退回区间内部而退出；说明两路证据同时出现时如何合并为一次退出动作、如何避免重复计减，以及退出时对已挂未成交单的撤销顺序。还需处理股票/ETF的T+1不可卖库存：当日新买部分无法立即卖出时，退出如何分批、残余敞口如何隔日处置。；相互影响：同时接收 entry_confirmation 的未确认结论与 range_detection 的结构失效判定，是两路证据的汇合点；其退出结果触发 reentry_policy 的冷却与恢复，并把已实现亏损与残余敞口传递给 capital_allocation。
- 规定失败退出后的冷却与恢复条件：同一标的需要满足哪些当时可见的条件才允许再次进入候选状态（例如区间重新成立、或确认条件被重新满足且间隔满足最短冷却），以及冷却期内是否允许观察但不参与。需明确冷却的计量方式与解除时是否保留旧区间的记忆。；相互影响：由 failure_exit 的退出类型驱动：结构失效与未确认两类退出可对应不同的冷却强度；其恢复结论决定何时可再次调用 entry_confirmation。同时受 capital_allocation 约束，预算缩减期间可允许再入场但规模更低或冷却更长。
- 在多个候选标的与多次失败之间分配资金、现金与单标的上限；当连续失败或已实现回撤出现时，如何缩减可用于突破试探与确认后建仓的预算，缩减按暴露单位还是按单标的额度表达；缩减后如何在后续连续成功中分步恢复，并确保恢复不依赖被覆盖的亏损记忆。；相互影响：接收 failure_exit 的实现亏损与残余敞口作为缩减触发来源；其预算状态回写至 entry_confirmation（收紧确认前试探规模与等待宽度）与 range_detection（收窄可接受区间宽度），形成资金约束回压识别与确认的闭环，使预算成为一等状态而非末端记账。

可研究的参数与结构选择：

- 区间成立所需的最短驻留长度（以完成日线根数表达）
- 区间边界被收于区间之外视为结构失效的持续条件
- 突破确认所需的连续收于边界之外的根数与确认前允许的试探手数上限
- 失败退出时撤销未成交单与分批减仓的优先顺序规则
- 冷却期的计量方式与解除条件（是否要求区间重新成立）
- 连续失败触发预算缩减的阈值与缩减阶梯，以及分步恢复的分级条件

持续维护依据：后续新揭晓的段数据可能显示：区间在多数时段被重新定义后边界频繁跳变（结构有效性问题）；突破信号与 NextOpen 实际成交之间存在系统性价差，导致确认条件在实盘序列中更难满足（信号执行差距）；连续失败后退出的残余敞口与T+1库存使预算恢复滞后于信号恢复（风险恢复问题）；以及预算回压改变确认宽度后，旧的持仓与区间记忆若不同步迁移会造成状态不一致（跨段兼容问题）。这些观察可能促使保持原逻辑、仅调整区间与确认的判定口径、或修改失败退出的合并规则与预算回压强度；不承诺每次维护都提升收益。
