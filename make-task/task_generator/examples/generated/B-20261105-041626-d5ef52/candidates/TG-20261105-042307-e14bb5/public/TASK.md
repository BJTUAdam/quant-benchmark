# 参与档位与回撤档位的双档位交接：证据分级、降档待办清理与分步回升

> v2任务规格。规格批准、数据绑定和运行接入分别记录，当前状态以task_input.draft.json与平台登记记录为准。

研究目标：在国内股票与ETF日线环境中，仅用当时已收盘的价量与账户数据：如何用带迟滞的状态辨识给出参与档位建议，并把组合层回撤证据独立地映射为降档触发；当参与档位下调时，哪些已挂未成交单、T+1新买不可卖库存与排队候选应随之失效、哪些应保留待恢复；当状态证据与回撤证据方向冲突时谁优先、如何避免同一段回撤被反复计为多档下调；恢复时如何要求参与档位与回撤档位分别取得互不沿用对方记忆的独立证据才逐级升档，并使迁移口径改变下一段可用的证据长度与允许动作集？

## 运行协议

先在研发期开发首版，再经历七段逐步揭晓的正式期。每段运行时冻结代码；完成后可以保持、调参或修改逻辑。
现金、持仓、未完成订单和JSON memory连续。修改不重置账户，不覆盖过去结果。全部七段的连续账户用于评价。
实际虚拟时间范围、数据版本和分段边界在绑定后确定。

## 研究决策

- 仅用已完成日线收盘数据构造当时可见的趋势/震荡证据，并给出带证据强度的参与档位建议；不得使用未来收益、事后成分或后续数据。；相互影响：输出作为switch_hysteresis的唯一输入；同时接收recovery_policy回写的证据长度与档位建议，使恢复期的辨识口径不同于降档前的口径。
- 为参与档位的进入与离开设定独立门槛与最短驻留，使档位变化需跨段延续才被采纳，避免在证据临界处频繁切换。；相互影响：向上接受state_identification的档位建议，向下决定participation_policy本期允许的参与档位；当drawdown_response已降档时，迟滞不得单独把档位升回。
- 把参与档位映射为可执行的动作集合，并明确回撤降档与状态迟滞降档同时生效时的优先级与去重规则，避免双重降档。；相互影响：接收switch_hysteresis与drawdown_response两路输入并裁决；其裁决结果决定已挂单与候选队列的处置，并作为state_migration需要迁移的动作集口径。
- 以组合层已回撤幅度、近期已实现波动与暴露集中度构造与参与档位分离的回撤证据，决定是否触发降档及降到何种程度，并处理T+1不可卖库存、挂单与现金不足下的分步减仓可行性。；相互影响：结果输入participation_policy作为第二路降档来源；同时把已执行的降档与未完成待办记入state_migration；其证据口径受recovery_policy调整。
- 规定参与档位与回撤档位各自的回升条件、所需独立证据与回升节奏，要求两者不同步回正，且不使用已被降档覆盖的旧记忆作为唯一依据。；相互影响：向上回写state_identification的证据长度与可用档位；其回升判定不得绕过switch_hysteresis直接升档；同时向state_migration声明哪些待办在回升后可被唤醒。
- 定义版本更新与跨段衔接时如何迁移已确认的参与档位、回撤档位、未完成挂单、T+1不可卖库存与待恢复候选队列，并说明旧口径下的档位证据不得自动沿用。；相互影响：回指participation_policy与drawdown_response，使迁移结果直接改变下一段可执行的动作集与降档残留；迁移中保留的未完成待办又反过来影响state_identification在恢复期可读到的证据长度。

可研究的参数与结构选择：

- 参与档位数量与各档位允许的动作集定义
- 状态证据的构成与迟滞确认的延续段数
- 回撤证据的构成、分级与触发降档的档位幅度
- 回撤与状态两路降档同时出现时的优先与去重规则
- 恢复期参与档位与回撤档位各自的独立证据与逐级回升节奏
- 迁移时未完成挂单与T+1库存的保留或清理口径

持续维护依据：后续正式期段落揭晓后，若出现降档后档位长期不回升、同一段回撤被反复触发多档下调、恢复后立即再次降档、或迁移后旧档位证据被自动沿用导致动作集错位，则说明证据分级、迟滞门槛或回升条件需要保持、调参或改逻辑。维护针对regime_transition、risk_recovery、state_compatibility与signal_execution_gap四项，观察揭示的是状态与执行偏差而非收益承诺，不保证每次维护都提升收益，也不要求实盘盈利。
