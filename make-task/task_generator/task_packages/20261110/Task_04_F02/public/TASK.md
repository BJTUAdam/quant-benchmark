# 重叠冲击的恢复证据：事件归属、重复参与与隔日库存预算

> 题目规格包：程序校验与本轮模型交叉审阅已完成；外部API复核未执行，未写入自动接纳库。数据待绑定，运行待接入。

研究目标：同一股票的冲击事件尚未恢复又发生新的价量冲击时，如何确定事件与恢复证据的归属，限制重复参与，并使多个事件研究台账、隔日锁定库存及统一账户预算连续一致？

## 运行协议

先在研发期开发首版，再经历七段逐步揭晓的正式期。每段运行时冻结代码；完成后可以保持、调参或修改逻辑。
现金、持仓、未完成订单和JSON memory连续。修改不重置账户，不覆盖过去结果。全部七段的连续账户用于评价。
实际虚拟时间范围、数据版本和分段边界在绑定后确定。

## 研究决策

- 研究同一股票尚未完成恢复时再次出现价量冲击，如何划分新事件、原事件延续和同一事件的重复触发；只以当时完成的日线分配事件编号与创建时事实。；相互影响：事件边界和创建时快照交recovery_path；合并与分裂决定资本预留和reentry_policy资格，不能把持仓后最大的波动追溯成最初冲击。
- 研究重叠事件下回摆、延续与未决证据的归属：同一根行情对旧事件和新事件可能方向相反，需要说明证据共享、占用或互斥规则及累计方式。同时研究回归实现、延续失效与持有时限分别如何触发旧仓退出或事件结束；明确未决事件不能无限占用库存。；相互影响：接收shock_detection的事件版本；将每个事件的可用恢复证据传entry_confirmation，事件归并时先经state_migration承接证据，不能复制一次反弹给多个事件并重复扩大参与。本模块给overnight_inventory输出退出需求与事件结束裁决；只有平台确认退出成交且关联未完成订单已处理后，才可将有库存的事件标为完成，不能把证据恢复等同实际平仓。
- 研究在当前事件集合上确认回归参与的时机，区分对旧事件追加、对新事件首次参与和禁止重复参与；确认只能依据当前已可见证据。；相互影响：接收recovery_path和reentry_policy，输出带事件归属的待办给capital_allocation；资金不足或旧事件库存未解除时，确认保留、降级或过期的规则须明确，不能按事件数量简单叠加买单。
- 将实际成交、T+1不可卖量、可卖量和未完成订单映射到事件研究台账；多事件台账的净量必须与平台统一真实持仓核对，不创建独立虚构子账户。；相互影响：接收capital_allocation的实际执行，向reentry_policy报告旧事件是否真正结束；归并事件或新参数不能使旧库存从台账消失，也不能把未卖出的旧仓当作空仓重开。
- 在同一股票多个事件以及不同股票事件之间研究净头寸上限、事件预留额度和重复证据的预算折减；预算按统一账户真实持仓约束，而非假设每个事件各有初始资金。；相互影响：接收entry_confirmation和overnight_inventory；事件合并经state_migration完成后才重新核算预留。预算反馈影响下一期确认等待，不在同一事件中循环改变已经使用的恢复证据。
- 研究旧冲击未清理、已退出后再冲击及事件合并后的再次参与资格，明确冷却对象是股票、事件簇还是恢复证据，并保留已经用过的确认信息。；相互影响：接收overnight_inventory和shock_detection，新机会需交entry_confirmation判断；未成交退出或不可卖库存不能被当作已完成旧事件而提前解除冷却。
- 研究跨段改变冲击划分或证据归属方法时，如何保持旧事件编号、已消耗证据、真实订单和库存研究台账可追溯；定义合并与分裂的守恒检查。；相互影响：接收shock_detection和recovery_path版本，映射结果传capital_allocation及overnight_inventory对账；迁移不重放历史买单，不复制旧仓，不重新获得已消耗的恢复证据。

可研究的参数与结构选择：

- 价量冲击的识别尺度与联合证据
- 事件簇合并、延续和分裂条件
- 恢复证据共享、占用或互斥规则
- 回摆、延续与未决状态的停留条件
- 回归实现、延续失效与最长持有期限的退出裁决及事件结束条件
- 首次参与与追加参与的确认差异
- 同票多事件净头寸和预留额度上限
- 重复证据参与的预算折减规则
- 事件、事件簇或股票级冷却的选择
- 隔日锁定库存的事件归属与释放规则
- 事件划分版本变更的台账迁移方法
- 真实订单、持仓与研究台账的守恒核对

持续维护依据：后续阶段可能从孤立冲击变为成簇冲击，恢复证据被多事件反复使用、冷却状态错配和旧库存重复归属的风险随之变化。维护可改变事件划分、证据去重、预算分摊或保留既有规则，但必须检查真实持仓守恒、已使用证据不复活以及未完成退出不丢失；这些行为是否改善长期运行由轨迹验证。

## 数据与执行

行情通过Tushare协议桥接器查询。使用环境变量MARKET_BRIDGE_URL和MARKET_BRIDGE_TOKEN，详见DATA_API.md。
名称与代码保持真实；全部时间字段使用虚拟时间，仅表示事件顺序和可见时点。
虚拟年份不对应真实历史年份，不得按年份预设股灾、政策、节假日或未来事件，也不得反推实际时期。
交易日以服务返回日历为准，不按虚拟日期的星期猜测；策略只能根据当时已可见数据形成判断。
只能使用当前可见信息，不访问外网。指数仅用于查询与基准，不可下单。
桥接器按平台传入的阶段范围累计披露；正式策略另受当前事件时钟限制。
显式请求任何未披露日期会整次报TIME_RANGE_EXCEEDED并记录，不能将错误解释为空行情。

任务只提供非生效的CPU/内存建议；单次运行时限由使用者本人明确选择，不预填。
