# 横截面反转事件的分批入场、隔日退出与换手额度竞争

> 题目规格包：程序校验与本轮模型交叉审阅已完成；外部API复核未执行，未写入自动接纳库。数据待绑定，运行待接入。

研究目标：当多只股票在不同时点出现反转候选时，如何把新事件排名与已有各入场批次的恢复程度、持有时限、T+1可卖性和退出需求一起管理？重点研究应保留多少额度处理旧批次退出，何时允许新增候选占用资金，以及同一股票多次触发时合并或拆分批次的后果。

## 运行协议

先在研发期开发首版，再经历七段逐步揭晓的正式期。每段运行时冻结代码；完成后可以保持、调参或修改逻辑。
现金、持仓、未完成订单和JSON memory连续。修改不重置账户，不覆盖过去结果。全部七段的连续账户用于评价。
实际虚拟时间范围、数据版本和分段边界在绑定后确定。

## 研究决策

- 研究只用当时数据定义短期价格偏离及归一化尺度，保留触发时参考值、波动尺度和事件编号。；相互影响：同一标的再次出现偏离时，rank_aggregation必须能区分新事件与旧事件未结束，不能事后以最低点重新编号。
- 研究成交活跃度和当前可交易限制如何约束反转参与，保留缺数据与确知不可交易的区别。；相互影响：筛选结果供rank_aggregation比较新事件；退出中的旧库存仍由exit_policy处置，不能因被筛除就从账户记录中消失。
- 在同一决策时点比较新反转事件，研究偏离强度、事件年龄和参与容量的权衡，以及已持有同标的是否新增批次。；相互影响：排序是capital_allocation的输入，不直接替代对旧库存的退出判断；不能因为旧仓跌得更深而无条件抬升其加仓优先级。
- 在新入场事件、待退出旧批次、当前现金和未成交占用之间分配整手资金，研究同一股票总风险上限。；相互影响：先扣除turnover_budget为旧批次保留的执行额度，再决定本次新增；每个实际入场归入overnight_inventory，不提前使用未成交卖出所得。
- 维护每个实际入场批次的可卖日期、成本、数量、触发参考和事件年龄，明确同股票批次聚合与费用口径。；相互影响：exit_policy先读取实际可卖库存和批次状态；当日新买批次不能借旧批次的可卖资格绕过T+1。
- 研究偏离恢复、机制失效与持有时限如何产生退出需求，明确同标的不同批次退出的排序和合并。；相互影响：输出退出需求及紧急程度给turnover_budget；尚不可卖或未成交部分必须持续保留，不能在指标恢复时假定仓位已经平掉。
- 在风险退出、普通恢复退出和新增入场之间分配当期换手与费用额度，研究退出积压时冻结、缩减或继续新增的条件。；相互影响：退出需求来自exit_policy，约束下期capital_allocation；先确认本期实际成交，再结转未完成额度和库存，不将预算重置误当完成退出。

可研究的参数与结构选择：

- 偏离参考窗口与标准化尺度
- 反转事件触发、延续和终止定义
- 重复触发事件的合并间隔与编号规则
- 新事件横截面排序及并列处理
- 进入前成交容量与涨跌停限制处理
- 同股票多批次合并或分开记账的规则
- 各批次恢复退出、失效退出与持有时限
- 可卖库存中退出批次的排序
- 风险退出与普通退出的预算层级
- 新入场预算与旧退出保留额度
- 组合及单标的上限、现金留存
- 未成交退出的重试、撤单和过期规则
- 参数更新后旧事件参考与年龄的兼容方式

持续维护依据：后续阶段可能出现反转触发密集、恢复变慢、不同批次挤占资金或多日无法退出。维护要判断改变事件定义、批次合并、退出优先级还是新增预算；任何改变都要接续旧批次的数量与可卖日期。七段不重置账户，研究记录应解释新增机会与存量风险的取舍，而非只报告单笔假设收益。
