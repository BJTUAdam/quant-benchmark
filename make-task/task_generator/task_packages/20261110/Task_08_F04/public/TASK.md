# 回撤风险贡献分解、流动性受限减仓与恢复额度管理

> 题目规格包：程序校验与本轮模型交叉审阅已完成；外部API复核未执行，未写入自动接纳库。数据待绑定，运行待接入。

研究目标：组合出现回撤时，如何区分风险集中于少数持仓与普遍恶化，决定按风险贡献、流动性或持仓比例分解减仓目标，并维护受T+1和交易限制影响的未完成减仓欠账？恢复额度必须同时考虑新的风险证据和旧减仓任务是否完成，不能仅因净值反弹就重开全部预算。 同一行情事件依次读取上次恢复授权、形成预算与减仓需求、核对实际执行结果、登记下次恢复授权，禁止在同刻循环重算。

## 运行协议

先在研发期开发首版，再经历七段逐步揭晓的正式期。每段运行时冻结代码；完成后可以保持、调参或修改逻辑。
现金、持仓、未完成订单和JSON memory连续。修改不重置账户，不覆盖过去结果。全部七段的连续账户用于评价。
实际虚拟时间范围、数据版本和分段边界在绑定后确定。

## 研究决策

- 仅使用已知账户、历史价格和当时持仓，研究组合回撤、波动与个股损益贡献集中度的联合证据。；相互影响：区分风险来源分散与集中后交给risk_budget；已卖出持仓的贡献与当前持仓敞口须分开，不把事后最低点当风险发生时点。
- 先选择并记录一个仅用当前可见桥接数据、能够产生现货多头目标的可执行基础参与规则及其版本，作为被控组合；不提供最佳选股公式。再将风险证据映射为组合目标暴露、单标的风险上限与允许新增额度，明确高水位和风险观察窗口。跨段若改变基础规则，须记录并与风险控制改动分开解释。；相互影响：本次预算只读取上一已完成行情事件记录并核销的恢复授权，随后向drawdown_response生成减仓目标；当前事件的新恢复判定不得反向重算本次预算，也不能抹除尚未完成的减仓责任。
- 根据已知成交容量、可卖数量和逐日交易限制描述各持仓可实现的减仓能力，缺失数据单独标记。；相互影响：向drawdown_response提供容量约束；可卖性差不代表风险更低，不能只卖容易成交的仓位后宣称目标风险已达成。
- 研究按损益贡献、当前敞口、流动性或组合规则分配减仓需求，并处理不可卖库存和受限委托。；相互影响：减仓需求传给turnover_budget形成执行优先级；目标减仓与已实现减仓分开存储，残余需求写入state_migration。
- 研究在减仓紧急程度、可成交容量和费用约束之间安排分批执行，同时明确风险退出与新增交易的预算关系。；相互影响：只用实际成交减少欠账；仍有未执行减仓时由recovery_policy决定能否恢复及最多恢复多少，不以挂单数量视作完成。
- 研究净值、风险集中度、实际暴露和减仓欠账何时共同满足恢复条件，选择整体恢复或按来源分步恢复。；相互影响：从state_migration读取减仓欠账和已用授权，先核对截至本次事件的实际成交，再根据本次证据登记至下一次已完成行情事件才生效的恢复授权；同一触发序号不重复授权，本次不再回调risk_budget求解。
- 用JSON保存风险证据版本、目标暴露、各标的剩余减仓需求、订单占用、已用恢复额度和触发序号。；相互影响：跨段和改版时先对齐真实账户与存量订单，再让recovery_policy处理新增恢复；不能因参数变更删除旧欠账或重置组合高水位。

可研究的参数与结构选择：

- 被控基础多头参与规则的选择、目标组合生成及版本冻结方式
- 组合高水位、回撤和风险观察窗口口径
- 个股损益贡献与当前敞口的分解方法
- 风险贡献集中度及证据等级
- 组合和单标的预算映射方式
- 减仓目标在各持仓之间的分配准则
- 容量、涨跌停及可卖库存估计
- 风险减仓排序和分批执行时效
- 风险退出与新增交易额度之间的关系
- 未完成减仓欠账的结转和取消条件
- 恢复触发条件与证据确认长度
- 恢复时按标的或按组合额度发放方式
- 欠账尚存时的恢复上限
- 同一风险事件的去重键和恢复额度核销
- 维护版本迁移时高水位、欠账和订单的兼容规则

持续维护依据：后续阶段可能出现风险由单一持仓向多标的扩散、流动性降低导致减仓迟迟未成，或反弹先于欠账完成。维护需要判断应改变风险归因、减仓分解、执行预算还是恢复授权，并解释这些改变对存量库存的影响。七段共享组合高水位及未完成减仓记录，不能重置后只统计恢复段表现。
