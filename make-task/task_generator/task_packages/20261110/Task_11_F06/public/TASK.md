# 跨期库存的撤退可行性：流动性枯竭、分腿减仓与到期接续

> 题目规格包：程序校验与本轮模型交叉审阅已完成；外部API复核未执行，未写入自动接纳库。数据待绑定，运行待接入。

研究目标：FG或M近远月价差进入后，若远月流动性下降或近月即将退出可交易集合，如何把可撤退容量作为配对资格和建仓规模的前置约束，并在分腿减仓、移仓或停用之间选择能承接实际库存的路径？不能只研究一条理想价差曲线的均值回归。

## 运行协议

先在研发期开发首版，再经历七段逐步揭晓的正式期。每段运行时冻结代码；完成后可以保持、调参或修改逻辑。
现金、持仓、未完成订单和JSON memory连续。修改不重置账户，不覆盖过去结果。全部七段的连续账户用于评价。
实际虚拟时间范围、数据版本和分段边界在绑定后确定。

## 研究决策

- 从同一品种真实合约中选择近远月组合，除当前可交易外，还需定义当时可估计的撤退资格，不能用未来成交量倒推最佳配对。；相互影响：流动性和预算会限制可选合约对；选择目标对时要考虑已有真实库存，不能每次重选后假定旧对瞬间消失。
- 基于已完成日线成交量、持仓量及已绑定交易状态分别评估两腿参与容量、缺失证据和流动性退化。；相互影响：筛选结果既影响新配对资格，也可能触发旧仓失效处置；旧仓不能因不再入选而从风险预算里删除。
- 将价差参与条件与撤退容量共同决定目标手数、持有时限及禁止加仓情形。；相互影响：目标进入分批库存队列，真实成交和占用反馈会重新约束下一轮目标；价差信号仍好但撤退容量不足时可维持、减仓或等待，须给出明确规则。
- 显式维护旧近月、旧远月及待建新月份的手数和挂单；规定分腿减仓、补对冲与撤单的优先次序。；相互影响：每次部分成交后重算剩余敞口和预算，不能把价差订单视作原子成交；失效退出与换月动作共享同一队列，不重复下达相反命令。
- 在旧仓清理、新仓建立和未完成订单之间分配真实腿预算，同时对过渡阶段的缺腿风险保留约束。；相互影响：预算决定是否允许边退出边建新对；不能以同品种跨期关系推断交易所保证金优惠，除非运行契约明确支持。
- 区分统计关系失效、撤退容量失效和到期资格失效，给出同时发生时的可解释处理优先级。；相互影响：先处理不可继续持有的合约风险，再考虑信号层重入；失败退出进入同一库存队列，并影响后续是否还允许选择同一月份。
- 设计到期前停止新建、分批平旧、转向替代合约对或暂停的路径，允许不移仓但必须处置到期风险。；相互影响：换月路径由真实库存和预算决定，不先拼接连续价差再假定账户完成移仓。换月失败时保留剩余状态供下一事件处理。
- 段间调参或改逻辑时，迁移已经部分退出的配对状态、失效标签和撤退队列；说明哪些阈值使用新版本、哪些订单先按旧意图清理。；相互影响：迁移先读取真实持仓与挂单，再重建待办，不能把版本切换当成一次平仓或重置初始资金；新队列仍受分腿执行和预算检查。

可研究的参数与结构选择：

- 候选合约对的最低剩余可交易期限
- 两腿流动性度量窗口及容量折扣
- 撤退资格的确认与解除条件
- 价差参与与退出门槛
- 建仓手数随撤退容量收缩的规则
- 分腿减仓与补对冲的优先级
- 缺腿敞口与挂单总占用上限
- 统计失效与到期失效的冲突顺序
- 停止加仓、平旧及选新对的时间窗口
- 跨段迁移时待办重建与旧单清理规则

持续维护依据：后续阶段可能揭示流动性指标高估撤退容量、退出先后顺序反而扩大缺腿风险、换月缓冲过短或版本迁移重复生成订单。维护要依据已经披露的执行差异调整资格、容量和队列规则；实际余额、各月份持仓、挂单和memory连续，未完成清理不得从结果中消失。
