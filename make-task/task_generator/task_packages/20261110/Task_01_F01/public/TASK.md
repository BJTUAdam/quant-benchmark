# 突破信号等待队列：成交受限时的信号有效期、撤回与区间版本交接

> 题目规格包：程序校验与本轮模型交叉审阅已完成；外部API复核未执行，未写入自动接纳库。数据待绑定，运行待接入。

研究目标：当多个突破信号因流动性、涨跌停或资金竞争而等待执行时，如何共同决定信号仍有效多久、哪些旧委托应撤回，以及新区间版本能否接续旧信号，使等待队列与真实成交和持仓连续一致？

## 运行协议

先在研发期开发首版，再经历七段逐步揭晓的正式期。每段运行时冻结代码；完成后可以保持、调参或修改逻辑。
现金、持仓、未完成订单和JSON memory连续。修改不重置账户，不覆盖过去结果。全部七段的连续账户用于评价。
实际虚拟时间范围、数据版本和分段边界在绑定后确定。

## 研究决策

- 仅用已完成日线建立有版本号的整理区间，区分边界更新、区间延续和结构失效；记录每个信号创建时所依据的区间版本。；相互影响：区间版本及有效性传给entry_confirmation和failure_exit；新边界不能追溯性地让旧信号重新成立，旧未成交订单由state_migration处理。
- 研究突破证据在等待下一开盘、部分成交或连续未成交后应如何衰减或失效；选择按信号年龄、结构变化还是成交反馈重新确认，而非无限重复原始买入信号。；相互影响：接收区间版本及liquidity_filter的可参与量；有效但尚未完成的确认形成待办队列，供turnover_budget排序；已耗尽有效性的信号送failure_exit撤回。
- 根据截至当前收盘已知的成交活跃度和涨跌停状态估计可参与规模，区分不参与、少量参与和允许继续等待；不使用下一根行情的成交量或日内排队数据。；相互影响：参与规模限制turnover_budget的下单量；实际部分成交与估计偏差只在后续已完成事件后更新下一期参与规则，不能修改当期已发订单。
- 在多个仍有效的突破信号及未完成订单之间研究预算预留、优先级和机会替换，区分已占用资金、未成交预留和可新分配现金；不得把未成交预留当作已持仓。；相互影响：接收entry_confirmation和liquidity_filter的候选，输出待执行顺序；撤回释放的预算只能在平台确认撤单或订单结束后供后续决策使用；反过来影响下一期entry_confirmation的等待成本。
- 分别判定结构失效、确认失效与订单执行失效，并研究撤销剩余买入量及已有成交仓位的处置；不能假设撤单指令瞬时生效或清退可绕过T+1。；相互影响：结构与信号失效来自range_detection和entry_confirmation；处置结果交给state_migration对账，未释放的占用继续留在turnover_budget中，不因逻辑退出而消失。
- 将区间版本、信号创建时刻、已成交量、未完成委托及失效原因保存在JSON memory；研究新逻辑如何承接旧队列和真实持仓，并建立一对一订单归属和可核对的注销规则。；相互影响：接收failure_exit与区间版本变化；迁移只影响下一决策时点的队列和预留，不重写历史成交。迁移后的队列与平台订单/持仓对账后，才能进入下一期turnover_budget。

可研究的参数与结构选择：

- 整理区间的因果构造与更新条件
- 突破确认的证据组合及等待长度
- 信号年龄衰减方式与最大存活条件
- 成交活跃度的回看尺度和参与上限
- 部分成交后保留剩余订单的条件
- 待办队列优先级和预算预留方式
- 新机会替换旧机会的门槛及成本表达
- 结构失效与执行失效的分流规则
- 区间版本切换时的订单迁移策略
- T+1受限清退的完成与残留判定

持续维护依据：后续阶段可能出现持续未成交、部分成交增多、区间频繁更新或候选竞争加剧。同一突破判据可能继续有效，但队列中信号年龄和订单占用发生变化，需要研究等待、撤回、替换或保持规则，并证明维护后旧挂单与已成交持仓没有被遗漏。效果须从实际轨迹检验，不承诺每次维护改善收益。
