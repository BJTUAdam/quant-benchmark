# 跨品种共享对冲腿的执行调度：组合净额、缺腿敞口与撤退预算

> 题目规格包：程序校验与本轮模型交叉审阅已完成；外部API复核未执行，未写入自动接纳库。数据待绑定，运行待接入。

研究目标：当SC/FU与FU/LU两个相对关系同时给出目标，且共享的FU腿在账户中只能表现为一个净持仓时，如何在价差级意图与真实合约净额之间分配容量、安排逐腿成交及撤退，并防止一组价差的未完成执行占用另一组的对冲资源？

## 运行协议

先在研发期开发首版，再经历七段逐步揭晓的正式期。每段运行时冻结代码；完成后可以保持、调参或修改逻辑。
现金、持仓、未完成订单和JSON memory连续。修改不重置账户，不覆盖过去结果。全部七段的连续账户用于评价。
实际虚拟时间范围、数据版本和分段边界在绑定后确定。

## 研究决策

- 明确每个品种的真实月份集合及配对关系，保证两个研究关系使用同一实际FU合约时才允许讨论共享腿净额。；相互影响：流动性筛选可以否决月份；换月时要区分同一品种不同合约，不能把旧FU和新FU在账户中错误抵消。
- 为两条相对关系分别给出可解释的统计或设定对冲口径，并按合约乘数映射为实际手数。；相互影响：只比较明确计价单位后的货币敞口，不把SC每桶与燃料油每吨直接相除当成固定物理转换；两个比例共同决定共享腿净目标。
- 将两组关系各自的参与/退出意图保存为可追踪的影子归属，再计算账户真实合约的净目标；明确冲突意图的优先级。 影子归属仅作为策略memory内的解释性账本，不构造可独立成交、开平或结算的虚拟子账户；只有真实合约净订单及系统成交能改变平台账户。；相互影响：真实净额不等于每组都已完成对冲。成交反馈需回写各组尚未完成的意图，不根据事后收益把同一FU成交重复分配给两组。 当两意图在共享腿恰好抵消时，记录意图变化但不虚构双方成交，也不将理想价差收益用于系统评分。
- 用当时已完成成交量、持仓量及已绑定的可交易状态约束单腿当期参与，缺失或不可交易不能视作零成本。；相互影响：筛选先影响月份资格，再限制本轮执行容量；只凭日线量不能声称知道下一根开盘深度或确定能成交。
- 设计目标到订单的分步调度，明确先减旧风险、补齐缺腿、开新关系与撤未完成单的先后；记录每组意图和真实净持仓的差。；相互影响：订单/成交回调更新预算占用和剩余动作。多腿不原子成交，若共享腿先成交而另一腿未成交，必须显式处理过渡敞口，不能虚构完整组合。
- 按账户真实合约净额和仍可能成交的未完成订单计算预算，并为未完成组合的撤退留出可用余量。；相互影响：预算逐事件重新约束调度；影子归属用于解释意图，不得把共享腿节约的账面手数重复当成两份可用现金或保证金优惠。
- 定义两组关系在完成、部分完成、冲突或超时状态中的保持、撤销和退出动作；说明共同腿何时可以净额抵消、何时必须先完成清理。；相互影响：真实成交后的归属变化回到信号意图，下一轮不得重复发送已完成部分；退出一组关系不能无解释地摧毁另一组仍需要的对冲。 退出或反向动作先与当前真实净仓、可用数量和仍有效订单对账，不能按两份影子头寸重复发送超过实际库存的平仓；开平与反向语义以绑定SDK验收为准。
- 处理各品种月份到期不一致造成的分段移仓，逐合约核对旧仓与新仓，不在换月时重置影子意图。；相互影响：移仓先改变月份映射，重新计算对冲与共享关系。移仓中途失败或某腿未成交时，剩余敞口和订单仍占用预算。

可研究的参数与结构选择：

- 两组关系的估计窗口与版本更新时间
- 各组残差参与门槛与退出门槛
- 冲突意图的优先级及同时参与上限
- 单腿参与率限制与最低流动性资格
- 分步调度的每次最大手数
- 未完成组合的超时与撤单节奏
- 缺腿敞口容忍度与强制减仓条件
- 共享腿净额及影子归属的重算周期
- 未完成订单的预算预留规则
- 退出/移仓期间允许新意图的条件

持续维护依据：后续阶段可能出现一组价差的退出吞掉另一组对冲、日线参与率限制导致缺腿库存长期残留、共享腿换月后影子归属漂移，或预算预留使有效机会无法开仓。维护应围绕调度优先级、占用口径和归属状态修正，现金、真实合约仓位、挂单与memory跨段延续，不以影子组合的理想收益替代系统实际成交结果。
